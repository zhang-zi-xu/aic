# 农心 Agent

AI+农业竞赛赛题五方向的基础工作区：从农业问题出发，把信息确认、农事建议、人工确认的任务和执行记录串起来。

本轮是框架与基础功能版本，不宣称已完成专业农业诊断、专家审核或竞赛性能验证。

## 架构

前端和后端独立构建、独立运行。Java 服务不再提供旧版前端页面。

```text
浏览器 → React 19 + TypeScript + Vite（3000）
                     │ /api 反向代理
                     ▼
             Java 21 + Spring Boot 3.3（8080）
              ├─ 对话 / Agent 工具 / 供应商代理
              ├─ 天气 / 城市查询 / 内置知识检索
              └─ SQLite：田块、记录、任务、会话
```

| 目录 | 用途 |
| --- | --- |
| `frontend/src` | React 界面、类型、API 客户端、设计样式 |
| `frontend/public/brand` | 本轮生成的 Logo 与品牌概念影像 |
| `frontend/dist` | 独立静态前端构建产物，不提交 Git |
| `server/src/main/java/com/nongxin` | Java controller → service → persistence / agent |
| `server/src/main/resources` | 配置、建表 SQL、知识与城市资料 |
| `server/src/test` | API、数据持久化、Agent 与风险判读测试 |
| `server/data` | 从 server 目录运行时的 SQLite 数据，不提交 Git |

## 启动

需要 Node.js 22.12+、JDK 21 和 Maven 3.9+。配置好 JAVA_HOME 与 Maven PATH。

**一键启动（推荐）**：双击项目根目录的 `启动农心.bat`，或双击桌面快捷方式「农心 Agent」（指向同一脚本）。它会自动补齐 JAVA_HOME、按需打包后端与安装前端依赖、检测 8080/3000 是否已在运行以避免重复启动，然后把前后端各放在一个独立窗口中启动，最后自动打开浏览器。关闭那两个窗口即停止服务。

脚本内容保持纯 ASCII：cmd.exe 按字节解析批处理，批处理里出现中文会在部分代码页下错位截断命令（曾导致启动失败），因此说明文字用英文。

**手动启动**（两个终端）：

终端一，在项目根目录安装前端依赖并启动：

```sh
npm install
npm run dev
```

终端二，在 `server` 目录构建并运行后端：

```sh
mvn package
java -Dfile.encoding=UTF-8 -jar target/nongxin-agent.jar
```

重新打包前请先停止正在运行的后端进程，否则 Windows 会锁定 `target\nongxin-agent.jar` 导致打包失败。

浏览器打开 http://localhost:3000 。右上角“模型设置”选择供应商、填写模型 ID 和 API Key，测试连接后保存。自定义接口须为支持 chat/completions 和工具调用的公开 HTTPS 接口；模型是否可用由供应商决定。

前端使用 `/api` 代理到 `127.0.0.1:8080`。Java 默认仅监听本机。若端口被旧版进程占用，请先停止对应项目服务，不要强行结束其他程序。

## 独立构建与检查

```sh
npm run build
npm run lint
npm test
```

前端产物在 `frontend/dist`；`npm run preview` 可本地预览产物，仍需要 Java 后端运行。

`npm test` 在隔离的测试环境中验证确认卡统一提交、流式解析、停止/失败重试、上下文隔离与历史管理，不调用真实模型、不读写你的数据库。

后端在 `server` 目录执行 `mvn test` 或 `mvn package`。测试使用单独的临时 SQLite 数据库，不写入你的田块和对话数据。重新打包前先停止正在运行该 jar 的进程，避免 Windows 文件锁。

## 对话请求如何工作

- **流式回答**：聊天使用 `/api/chat/stream`（SSE），文字增量先于完成显示；工具阶段显示“正在核对资料”等真实状态。只有收到 `done` 事件才算完整回答；断开、出错和超时的回答标为“未完成”，不会作为完整历史发给模型。
- **部分完成（degraded）**：工具已产出方案/风险卡、但供应商随后失败或超时时，回答标注“部分完成”，卡片保留可继续使用，也可重试同一条问题；这类回答同样不带入后续对话历史。
- **保存与重试**：用户问题先保存再调用模型；保存失败不调用模型，可单独“重试保存”。重试复用同一条用户消息及其田块/天气快照，不会新增重复问题。同一会话的保存按顺序串行提交。
- **上下文快照与窗口**：每条问题固定当时关联的田块和（可选）天气快照，重试沿用快照，不自动替换为后来修改的数据。天气默认不发送，需在输入框上方勾选；换会话/换田块会取消勾选。较长对话只携带最近 20 条有效消息，可在右侧“下条问题的背景”查看提示。
- **历史管理**：会话重命名只改标题；删除需二次确认且不可撤销（不删除田块与已建任务）；操作失败保留原列表。
- **`/api/chat` 保留**：模型设置中的“测试连接”仍使用非流式接口，与聊天流式接口互不影响。

## 可信资料与可追溯引用（P1）

- **来源登记**：`server/src/main/resources/knowledge/sources.json` 登记每篇原文的标题、机构、URL、发布日期、抓取日期、适用地区、适用作物、许可说明与核验状态；片段保留章节/定位信息，可回查原文。
- **核验状态不混用**：已逐条对照原文登记的标为「已核验原文」，可点开链接核对；本地整理草稿统一保持「未核验」，只作线索，不能声称官方已确认。
- **混合检索（关键词 + 向量 + 知识图谱）**：三路召回后用 RRF 融合排序。
  - 关键词路：加权打分 + 元数据过滤（作物硬过滤、地区按同区优先排序而不硬排除）；必须有标题/关键词级命中，仅正文偶然命中不算依据；同主题下已核验原文优先于本地草稿。
  - 向量路：EmbeddingService 把片段向量化（标题/作物/主题/生育期/关键词 + 正文）存入 SQLite kb_vectors 表，按余弦相似度召回，用于接住"叶子像被开水烫过"这类无字面重合的口语表述。默认模型 BAAI/bge-m3（OpenAI 协议，可换供应商）；未配置密钥时自动禁用该路，检索行为与纯关键词完全一致。
  - 图谱路：KnowledgeGraphService 从片段自动构建实体图（作物/主题/生育期/关键词→片段，同文档共现），对查询实体与已命中片段做一跳扩展，补足结构化关联。图谱节点全部由资料片段推导，不会出现"图谱里有、资料库里没有"的凭空事实。
  - **可评估**：POST /api/kb/eval 用 12 条口语化提问对比两种模式，GET /api/kb/status 查看索引与图谱规模。
- **检索效果（可复现）**：同一评估集下，关键词 Top3 命中率 25.0%（3/12）→ 三路混合 91.7%（11/12）；提升集中在"叶子像被开水烫过一样发白枯萎""稻丛基部一层小白虫"这类不含术语的口语提问。该数据为本地哈希向量模式（离线可跑）测得，配置真实 embedding 模型后可用同一接口复测。剩余 1 例失败源于资料库未覆盖该主题（倒伏），属资料覆盖问题而非检索算法问题。
- **引用校验**：模型只能引用本次检索返回的来源ID；处方里的依据（含嵌套结构、非列表形态）若不在本次命中集合中会被后端清空并计数说明；正文里出现的未命中来源ID会被替换为明确提示；对话中的「资料依据」卡由后端从资料库生成，保存会话时也由后端按 ID 重建，客户端无法伪造状态或链接。
- **回答分区**：回答区分「你提供的事实」「资料支持的判断（带来源与适用条件）」「仍需核实的信息」；不足以确认病害、农药登记与用量时输出核查步骤，不补写剂量。
- **当前覆盖**：水稻（长江中下游/浙江）与小麦（黄淮/河南）共 5 篇权威原文 + 17 条未核验草稿；已核验原文与同主题草稿同时命中时，原文优先。用例与准确率见 `docs/P1-检索用例与来源登记.md`。

## 已接通的基础流程

- **问农心**：可配置供应商/模型/API，真实接口请求，多轮对话与会话持久化；停止等待、失败重试、Markdown 导出。请求机制（流式、快照、保存顺序）见上一节。
- **补充确认卡**：各题答案独立保存，选好后点击“提交并继续”，按问题顺序整理成一条完整用户消息并发送；支持自行填写和“暂不确定”，不会覆盖输入框草稿。
- **农情数据**：粘贴或导入 TXT/CSV，先预览再附加，超限明确提示而不是静默截断。不支持图片诊断。
- **我的田块**：新建、编辑、删除、日常观察记录；只显示实际录入的信息，不播种演示数据。
- **农事任务**：手动新建，或从结构化建议确认加入；日期可待定，支持筛选、完成、执行备注、复查要求。
- **农技资料**：按来源登记浏览与检索，标注「已核验原文」或「本地草稿 · 未核验」，可查看机构、日期、适用地区与原文链接。
- **天气与时间**：左侧紧凑模块；设备定位需用户授权，城市搜索不需定位权限；显示来源、数据时间和错误，本机时钟单独标注。

对话中更换田块会新开对话，避免把不同田块混在一起；建议加入任务并不代表任务已执行。

## 数据与安全边界

- API Key 保存在浏览器 sessionStorage，只经 Java 转发到用户选择的模型供应商；不写入数据库、源码或日志。切换供应商会清空当前密钥。
- 农情数据、田块信息及会话会发送到所选模型供应商。不要上传不必要的个人信息或商业敏感内容。
- 当前为**本机单用户原型**，还没有账号鉴权与用户隔离。不要直接公网暴露 API。公网部署前须补充鉴权、限流、HTTPS、备份和供应商审计。
- Java 默认监听 `127.0.0.1`，受控部署可用 `SERVER_ADDRESS` 调整。独立部署前端时，由 Nginx 等网关将 `/api` 转发到 Java，前端其他路径回退到 `index.html`。
- 数据库路径相对于后端启动目录。固定从 `server` 目录启动，备份 `server/data/nongxin.db` 后再迁移环境。
- 背景是 AI 生成的品牌概念影像，不是用户田块照片、卫星图或实时监测结果。

## 已知限制

- 本机开发版本：尚未完成公网鉴权、HTTPS 与限流，不要公网部署。
- 供应商不兼容时：不支持流式或工具调用的网关会返回明确错误；网关忽略 `stream=true` 返回普通 JSON 时会被接受，并在状态中说明“未采用流式输出”。
- 停止回答不等于供应商停止计费：断开会尽快终止本机连接，但上游已产生的费用无法保证撤销。
- 仅发送最近 20 条有效消息，没有长对话摘要或事实记忆；历史天气快照过期后只提示重查，不会悄悄更新原问题。
- 资料库只摘录与问答相关的段落，未收录全文；覆盖水稻与小麦两类作物、长江中下游（浙江）与黄淮（河南）两个地区，其它作物或地区会检索不到依据，此时系统应明确回答“没有查到可引用的依据”。
- 检索默认具备关键词 + 图谱两路；向量路需配置 embedding 密钥（NONGXIN_EMBEDDING_KEY）后启用。未配置密钥时，口语化表述的召回仍与改造前一致（同义表述、错别字覆盖有限）。本地哈希向量模式（NONGXIN_EMBEDDING_MODE=local）可离线跑通全链路，但语义泛化弱于真实模型，仅用于链路自检与断网兜底。
- 不支持图片诊断。
- 真实付费模型的端到端联调依赖有效凭据；自动化测试全部使用 mock，不产生费用。

## 下一阶段，不在本轮冒充完成
