## 一、本轮实现了什么，用户如何操作

1. **弹窗与历史管理恢复可用**：重命名/删除对话的弹窗此前在测试环境中因缺少 `requestAnimationFrame` 崩溃，现已修复；重命名只改标题、删除二次确认、取消不产生请求、失败保留列表均有自动化验证。
2. **前端测试从 65 秒降到 2.9 秒**：查出真正的病根——`assert.equal(元素, null)` 失败时 node:assert 用 `depth:1000` 检查整棵 JSDOM 文档再跑 Myers diff，每次抛错 45—65 秒，`waitFor` 每 50ms 轮询都在重算。断言改为布尔比较后消除。**这是测试写法问题，不是产品缺陷。**
3. **流式端点修复真实缺陷**：`ResponseEntity` 包裹 `SseEmitter` 会被 Spring 路由到消息转换器并抛 `No converter for SseEmitter`（生产同样 500）。改为直接返回 `SseEmitter` + 响应头注入；工作线程池饱和改为 `Overloaded` → HTTP 429。
4. **“部分完成”状态贯通**：工具已产出方案/风险卡、但供应商随后失败或超时时，回答标注“部分完成”，卡片保留可用、可重试同一条问题，且不进入后续对话历史。此前这类结果会被伪装成正常完成。
5. **保存按顺序串行提交**：同一会话的保存串行化，迟到的旧响应无法覆盖新消息；新增自动化验证（挂起第一次保存，确认第二次排队而非并发发出）。
6. **体验整理**：流式跟随改为即时贴底（不再被 CSS `scroll-behavior:smooth` 反复打断）、切换会话自动回到最新消息；部分完成与未完成使用不同提示文案与配色。
7. **文档与脚本**：README 补流式/半成品/快照/上下文窗口/已知限制；`启动农心.bat` 修正为前后端双启动 + UTF-8 + 正确端口；清理废弃的历史列表样式选择器。

## 四、迁移、凭据、部署与使用限制

- 无数据迁移、无凭据写入；测试全部使用临时 SQLite 与 mock 供应商。
- 停止回答不保证上游立即停止计费；断开只保证尽快终止本机连接。
- 仍为本机单用户原型，未做鉴权与用户隔离，不要公网暴露。
- 仅携带最近 20 条有效消息，无长对话摘要；历史天气快照过期只提示重查。
- `App.tsx` 大规模拆分**有意推迟**：本轮已有 19+67 个测试作为保护层，但拆分属独立重构，风险与收益不成比例，建议用户验收通过后单独进行。
