# 体验与流程改动记录（2026-09-11 ~ 09-12）

本文记录 P3 之后、进入 P4 之前的一轮集中改进：**全部来自真实使用反馈**（用户导出对话 + 截图 + 语音），每条都附可核验证据。
路线图见 `docs/开发交接与后续实施清单.md`；P0/P1/P2/P3 的验收报告在 `docs/P0-…`、`P1-…`、`P2-…`、`P3-…`。

## 一、流程：先问完，再给方案（用户原话："问完所有要问的额外信息之后再给出方案"）

**问题**：每轮都给方案卡 → 一次性返回文字太多难读，还容易产生重复任务。

**改法**
- 提示词新增【一轮一件事】：信息没问完时**只做两件事**——① 简短判断；② 用 `submit_clarify` **一次性把要问的问完**（≤3 项）；**本轮不调用 `submit_farm_plan`**，正文也不排时间表。
- 用户答完卡、信息齐了之后才提交方案，**一次只给一张卡**。
- 正文长度预算：默认 **400 字以内**，判断段 3 句以内。
- `submit_clarify` 的返回文本同步改为"这一轮不要提交处方单"。

**证据**：`server/.../controller/ChatController.java`（提示词块）、`agent/AgriTools.java`（工具返回文案）；`ChatControllerTest` 与 `AgriToolsTest` 锁定这些句子。
**真机复测（deepseek-chat，带水稻病叶照片）**：第一轮回答＝判断段 + 一张确认卡，**没有处方单**；第二轮追问后才给方案。

## 二、内容：第一句必须给判断（用户原话："到最后也没说我的水稻到底怎么了"）

**问题**：模型把"卡片已提交"当成回答，正文没有结论。

**改法（两层，不靠模型自觉）**
1. 提示词：**第一句必须先给判断**（最可能是什么 / 凭什么 / 不太像什么），允许不确定但**不许用"信息不足"代替判断**；判断必须带"看到 X 就说明判断错了、要改成 Y"；同一会话最多追问一轮；只给处方单没有判断段＝没有回答。
2. **服务端兜底**：`ChatController.lacksVerdict(reply)` 检测正文缺少判断句（且提交了处方单或确认卡）时，自动补一轮"只写判断段"（≤200 字，不带工具），把结果**拼在回答最前面**；失败则原样返回，不伪造结论。

**证据**：`ChatController.java`（`VERDICT_RE` / `lacksVerdict` / 结论兜底轮）；单测 `cardOnlyRepliesGetAVerdictParagraphAddedInFront`。
**真机复测**：首句「**最可能是叶瘟**：叶面上是两头尖的梭形斑…不太像胡麻斑病…也不像细菌性条斑」，并附可推翻条件；后端 124/124 通过。

## 三、任务：自动合并重复（用户原话："有重复的就保留一条"）

**问题**：模型每轮重排方案卡，方案项 ID 只在单条消息内唯一 → 跨轮点"加入任务"会堆出孪生待办（实测 15 条里 4 对完全重复）。

**改法**
- **源头**：`TaskService.create` 除按（来源消息＋方案项）幂等外，再按「**同田块＋同名未完成**」复用已有任务，不新建。
- **前端**：只有**最新一张方案卡**能加入任务；旧卡显示"已过期"徽标并撤掉按钮。
- **启动清理**：`TaskService.mergeDuplicates()` 每次启动自动合并——同一田块＋同名＋同日期＋未完成＋**没有任何执行/复查记录**的，只留最早一条；已完成/已取消不参与，日期不同的同名任务视为两次安排不合并。

**证据**：真实库实测 `15 → 11 条`，日志 `[task] 启动自动合并重复任务：清理 4 条`；单测 `duplicateTasksAreMergedAutomaticallyButRecordsAreNeverDiscarded`（构造 5 条，断言只删 2 条、带记录与不同日期的保留）。
**数据安全**：每次启动仍留快照（`server/data/backup/startup-v4-*.db`，保留 10 份），误删可回溯。

## 四、可读性：给农民看的字号（用户原话："字太小，看那么小那么多的字会太累了"）

方案卡正文 12→**15px**、标题→**16px**、行高 1.9；任务行标题→**15.5px**、条件/方法/备注 10→**13.5px**；按钮触控高度≥36px（手机 40px）；来源卡摘录→13.5px。
**证据**：`frontend/src/styles/globals.css` 末尾「可读性」区块（集中覆盖，便于再调）。

## 五、任务页：先按田块分组，组内按时间（用户原话："没法清晰看到先做哪个，也没区分田块"）

- **组**＝田块（含"未关联田块"），组头显示 田块名 · 作物 · 条数 · **最早日期**；组之间按最早任务日期排。
- **组内**：待确认优先（它挡着后面的事）→ 日期升序 → 同日期按创建时间；每行左侧有**序号圆标**，从上往下即执行顺序。
**证据**：单测 `tasks are grouped by field first and ordered by time inside each group`（3 组、组头顺序、组内顺序、序号 1/2/3、组头"3 项 · 最早 2026.09.11"）。

## 六、图片：粘贴即可（用户原话："没法直接把图片粘贴到输入框"）

Ctrl+V 直接贴截图；**缩略图显示在输入框内**（textarea 上方）可单张删除；一次最多 3 张；把图片文件拖进输入框同样可用；纯文字粘贴不受影响。
**证据**：`lib/images.ts`（校验/压缩/上传共用链路）、`image-attach.tsx`（`ImageStrip`）、单测 `pasting an image from the clipboard uploads it and shows it inside the composer`、`pasting plain text keeps the browser default and does not upload anything`。

## 七、田块影像档案：照片按田块与时间沉淀（用户提议）

- 聊天里发的照片**默认存入当前对话关联的田块**（界面明确写"将存入 甲田"；未关联则不归档）。
- 田块页新增**「田间照片」时间轴**：按拍摄日期倒序、显示占用体积（张数 · MB）、可单张删除（同时删磁盘文件）。
- **「让农心看最近状况」**：新开该田块对话 + 预填问题 + 自动带上最近 3 张。
- 作曲区有默认勾选、**写明日期**的「带上最近 N 张田间照片」开关——不会每条消息都偷偷塞旧照片。
**证据**：`UploadService`（归档字段、占用统计、删除）、`UploadController`（`POST /uploads` 带 fieldId/observedAt/note、`GET /uploads/field/{id}`、`PATCH`、`DELETE`）、迁移 **v4**；前端用例 3 条（时间轴/删除、让农心看最近状况、开关传参）。

## 八、语音输入（浏览器自带识别，零配置）

作曲区麦克风按钮：Chrome/Edge/安卓 Chrome 可用（**iOS Safari、Firefox 不渲染按钮，不放假的**）；识别结果**只追加到输入框、可编辑、绝不自动发送**；错误文案说人话；**音频由浏览器厂商的识别服务处理，不经过本项目后端**。
**证据**：`voice-input.tsx`；用例 `no fake microphone button when the browser has no speech recognition`、`recognised speech is appended to the composer and never sent automatically`。
**已知前提**：手机上麦克风与定位都需要 HTTPS（浏览器规定），局域网 HTTP 下只能打字。

## 九、手机访问（不上线的交付方式）

- 新增 **`启动农心-手机模式.bat`**（纯 ASCII，已校验）：前端绑 `0.0.0.0`、后端仍只监听回环，自动打印本机局域网地址与防火墙提醒。
- 应用内新增 **「手机访问」**：`GET /api/network` 枚举内网 IPv4 → 界面用 `qrcode.react` 生成**二维码**（只含 `http://内网IP:3000/`，不含密钥或聊天内容），并如实提示"同一 Wi-Fi 的人都能访问，请只在自家网络使用"。
**证据**：`启动农心-手机模式.bat`、`NetworkController.java`、`mobile-dialog.tsx`；实测接口返回 `10.192.48.76(wireless)`。

## 十、稳定性：不再白屏

用户报告过一次白屏，根因是自动定位里 `navigator.permissions.query()` 在部分浏览器**同步抛错**、异常冒到渲染期。已修（try/catch 包住，失败就跳过自动定位），并新增**错误边界**：渲染期异常显示可读原因 + 「重新加载 / 清掉本地界面设置后重试」，不再白屏。
**证据**：`components/ui/error-boundary.tsx`、`main.tsx`、`App.tsx` 自动定位 useEffect。
