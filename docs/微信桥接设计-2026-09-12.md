# 微信桥接设计（2026-09-12）

目标：让农户在**微信里**就能问农心，并复用已有的田块上下文与任务闭环。
范围：**本地进程 + 扫码登录**，不依赖公网服务器、不需要备案（见 `docs/开发交接与后续实施清单.md` 第 2.5 节"上线部署：已评估为不需要"）。

## 二、架构

```
微信用户 ──(扫码登录后由 SDK 维持长连接)── wechat-bridge 进程
                                              │  ① 文本 → POST /api/chat（127.0.0.1:8080）
                                              │  ② 回复 → 渲染成微信可读的纯文本
                                              │  ③ 命令 → POST /api/tasks（加入任务）
                                              └─ 本地 SQLite：联系人 ↔ 会话映射、最后一张方案卡
```

- 桥接是**独立进程**（新目录 `wechat-bridge/`，Maven 模块），失败不影响网页端；
- 默认**只监听本地**与后端通信，不开放任何入站端口；
- 农心后端地址可配置（`nongxin.base-url`，默认 `http://127.0.0.1:8080`）。

## 三、会话与状态映射

| 微信侧 | 农心侧 | 说明 |
| --- | --- | --- |
| 用户（`userId`） | 一段固定会话 `conversationId` | 首次收到消息时创建；保持上下文连续 |
| 用户绑定田块（可选命令 `绑定 甲田`） | `field` 字段 | 绑定后每条消息都带上该田块档案；未绑定则与网页端"不关联田块"一致 |
| 最近一张方案卡 | 内存 + 本地表 | 用于"加入 N"命令；只保留每个联系人最近一张，避免重复任务 |

## 四、文本渲染规范（微信里显示不了卡片）

| 网页端组件 | 微信里的呈现 |
| --- | --- |
| 正文（判断段 + 说明） | 原样文本（提示词已限制 400 字以内） |
| 方案卡 | `【农事方案】标题` + 编号列表：`1) 动作（窗口：… 条件：…）`，末尾 `回复「加入 1 3」把第 1、3 项记进任务` |
| 确认卡 | `需要确认：` + `1) 问题（可选：A/B/C）`，末尾 `回复「1A 2B」或直接说答案` |
| 来源卡 | `依据：机构《标题》发布日期 链接`（最多 3 条） |
| 风险筛查 | `【农情数据筛查】…`（原样文本） |
| 状态标记 | `（回答未完整生成，可回复「重试」）` |

## 五、命令集（v1）

| 命令 | 行为 |
| --- | --- |
| 任意文本 | 走 `/api/chat`，按上表渲染回复 |
| `加入 1 3` | 把最近方案卡的第 1、3 项登记为任务（`pending_confirmation`，幂等，不会重复） |
| `任务` | 列出进行中的任务（按田块分组、带日期，最多 8 条） |
| `绑定 甲田` / `解绑` | 绑定/解除默认田块 |
| `重试` | 重发上一次问题 |
| `帮助` | 命令说明与隐私提示 |

## 六、安全与合规（必须做，不是可选项）

1. **第三方协议风险**：`wechat-ilink-sdk` 不是腾讯官方接口，个人号自动化违反《微信个人账号使用规范》，**有封号风险**。因此：
   - **演示与试用一律用小号**，不使用主号；
   - 竞赛材料中**如实标注**"微信通道基于第三方 SDK `wechat-ilink-sdk`"，不写成自研；
   - 桥接进程**默认不启动**，需要显式运行；启动日志与界面都提示风险。
2. **只回私聊**，不处理群消息（v1）；不支持主动群发、不做营销类调用。
3. **限频**：每人每分钟 ≤ 3 条、每日 ≤ 200 条，超限回复"稍后再问"；避免高频触发风控。
4. **隐私**：桥接日志只记录 `userId 哈希 + 字数 + 耗时`，不落消息正文；与网页端一致，密钥不落库不落日志。
5. **失败即降级**：后端不可用时回复"农心暂时连不上，请稍后再试"，不编造答案。
