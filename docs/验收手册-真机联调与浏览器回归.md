## 一、前置准备（约 3 分钟）

1. 双击桌面「农心 Agent」图标（或项目根目录 `启动农心.bat`），等浏览器自动打开 http://localhost:3000 。
   - 若前端/后端已在运行，启动器会显示 `[skip]`，只打开页面，不会再起重复进程。
2. 右上角「模型设置」→ 选供应商 → 填模型 ID 与 API Key → 「测试连接」→ 看到「已收到模型回答，连接可用」→ 保存设置。
   - 测试连接走的是非流式 `/api/chat`；它通过说明密钥与地址没问题。已实测过：把密钥填错时，这里会显示「供应商鉴权失败，请检查 API 密钥与模型权限」。
3. 左侧建立测试田块（部分用例需要）：
   - 甲田：作物「水稻」，播期 `2026-06-01`
   - 乙田：作物「小麦」，播期 `2026-05-01`

**记录的通用做法**：每跑完一个用例，用右上角「导出当前对话」下载 `.md`（现在包含来源卡、核验状态与"未完成/部分完成"标记），或截图 + 结论填到文末结果表。

## 二、真实模型联调用例

### T1 · 有命中依据的水稻问题
- 田块：甲田（水稻）
- 输入：`我这边水稻刚开始破口，稻瘟病要怎么防？`
- 通过标准：
  1. 回答把信息分开说：**你提供的事实** / **资料支持的判断** / **仍需核实的信息**（不必有标题字样，但三块内容要能分清）
  2. 正文出现来源ID（形如 `chunk-pest-rice-blast`）或标题+机构+日期
  3. 下方出现「资料依据」卡：状态为**已核验原文**、有机构、发布日期、适用地区/作物、可点开的原文链接
  4. 如果提到药剂：只给核查方式（查当地登记标签），**不写具体剂量数值**
- 失败判定：编造剂量；来源ID 与卡片对不上；卡片里出现「已核验」但链接打不开或与标题不符。

### T2 · 小麦 + 连阴雨赤霉病（验证地区/作物匹配）
- 田块：乙田（小麦）
- 输入：`小麦抽穗扬花期碰上连阴雨，赤霉病要不要打药？`
- 通过标准：引用 `chunk-henan-scab` 或 `chunk-pest-wheat-scab`；要点与原文一致（齐穗至扬花初期首防、"见花打药"、施药后 4 小时遇雨补治、连阴雨隔 5—7 天轮换）；**不出现水稻资料**。

### T3 · 没有资料的问题（验证不编造）
- 输入：`柑橘黄龙病怎么防治？`
- 通过标准：明确说明**没有查到可引用的依据**，给出"下一步怎么核实"；不编造药剂与剂量；不应出现"已核验原文"的来源卡。

### T4 · 跨作物隔离
- 田块：甲田（水稻）
- 输入：`小麦赤霉病怎么防？`
- 通过标准：不把小麦资料当作本块依据；可提示作物不符或追问确认；不得直接给小麦处方。

### T5 · 确认卡闭环
- 输入：`我的稻子最近不太对劲，帮我看怎么办`
- 通过标准：出现确认卡（最多 3 题，带选项）→ 逐题选择/自填/"暂不确定" → 点「提交并继续」→ 聊天里出现**一条**包含全部问答的用户消息 → 模型接着回答。
- 附加检查：提交前在输入框里打一段草稿，提交后草稿仍在、没被选项覆盖。

### T6 · 停止与重试
- 发一条会较长的问题，生成中点「停止回答」
- 通过标准：该回答标注「回答未完成」；点「重试这条问题」后，历史里**只有一条**原始用户消息（不产生重复问题）；重试沿用原问题的田块/天气快照。

### T7 · 提醒（可选）
- 若回答显示「部分完成」（工具结果保留但生成未完成），确认：卡片仍可用、可重试、该回答不进入后续上下文。

## 三、浏览器回归清单

**视口**：1440 宽 → 1024 宽 → 390 宽（DevTools 设备模拟 iPhone 12）
**缩放**：浏览器缩放到 200%，检查不出现横向滚动、文字不重叠、按钮可点

| # | 项 | 检查点 |
| --- | --- | --- |
| B1 | 中文输入法 | 拼音组合状态下按 Enter **不**误发送；确认候选后才发送 |
| B2 | 键盘 | `Enter` 发送、`Shift+Enter` 换行；`Tab` 焦点顺序合理、可见焦点环 |
| B3 | 弹窗焦点 | 打开「模型设置」/删除确认：焦点进入弹窗、`Esc` 可关、关闭后焦点回到原按钮 |
| B4 | 移动端 | 390 宽下输入框、发送/停止按钮、确认卡逐题、来源卡均可操作；侧栏抽屉可开合 |
| B5 | 农技资料页 | 按作物/状态筛选、搜索、点开详情、原文链接 `target=_blank` 新窗口打开；「本地草稿 · 未核验」与「已核验原文」标注正确 |
| B6 | 来源卡 | 折叠/长摘录不撑破布局；无原文链接的草稿显示"无原文链接" |
| B7 | 流式滚动 | 生成中往上滚阅读，屏幕**不**被强制拉回底部；靠近底部时正常跟随 |

| B9 | 关联田块下拉 | 点开为自绘弹层（非系统菜单）：当前项带勾选、鼠标悬停高亮、键盘上下+回车可选、`Esc` 关闭、底部「管理田块档案」进入田块页 |

| B12 | 页面内到期提醒（P2） | 任务页顶部出现「今天要留意」：已逾期 / 今天到期 / 执行完等复查，点击可切到对应筛选；文案明确说明不会发送短信或推送 |
| B13 | 方案项幂等（P2） | 同一条 AI 方案卡连点两次「加入任务」，只登记一条任务；卡片显示「已加入任务」并提示重复点击不会再加 |

## 六、体验面优化（2026-09-10 追加，对应 B9/B10）

**背景**：用户反馈两处体验问题——①会话栏的「关联田块」是原生 `<select>`，系统菜单无法定制、观感简陋；②侧栏「最近对话」平铺混排，田块一多不好找。

**改动**

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| 会话栏 · 关联田块 | 原生 `<select>` | 自绘下拉 `NxSelect`（`frontend/src/components/ui/nx-select.tsx`）：田块图标 + 田块名 + 作物副标、当前项勾选、悬停高亮、底部「管理田块档案」入口 |
| 资料页作物、任务页田块/状态筛选、设置页供应商 | 原生 `<select>` ×5 | 同一套 `NxSelect`，工具条内使用 `.nx-filter-trigger` 尺寸 |
| 侧栏 · 最近对话 | 平铺列表 | 按田块分组（组头＝田块名 · 作物 + 条数徽标），每组可独立折叠，组内缩进；未关联田块的会话单独成组，分组顺序按最近活跃 |

无数据来源变化：分组只用会话已有的 `fieldId`，未新增任何假数据；田块改名后刷新即按新名字显示。

**验证方式（本次）**

- `npm test`：**24/24 通过**，其中新增 2 条用例——「最近对话按田块分组、各组独立折叠」「下拉为自绘弹层、列出田块与作物、底部可进田块管理」。
- `npx tsc --noEmit` 与 `npx tsc -p frontend/tsconfig.test.json --noEmit`：0 错误；`npm run lint`：0 告警；`npm run build`：构建通过。
- Edge 无头截图人工核对：主界面（会话栏下拉收起态、侧栏三组对话）与自绘弹层展开态（勾选/高亮/底部入口、层级覆盖正确）。
- 未做真实模型问答，因此不影响 T1–T7 的既有结论。

**顺带修掉的一个测试环境坑**：jsdom 26 的 nwsapi 把 `:modal`/`:fullscreen` 实现成对 `element.matches()` 的回调，而 `@floating-ui` 定位弹层时会调用 `matches(':modal')`，两者互相递归到栈溢出并被 nwsapi 吞掉后重试，导致**任何打开自绘弹层的用例卡 1~3 分钟**（实测 `chat.test.tsx` 单文件 265 秒、CPU 采样里 `matches` 调用 2.65 亿次）。已在 `frontend/tests/setup.ts` 里短路这两个伪类（测试环境不存在顶层弹层），修复后 `chat.test.tsx` 265 秒 → **约 11 秒**，全套件 24 条 11.4 秒。这是纯测试环境问题，浏览器不受影响。

**后续回归建议**：改动 `NxSelect` 或侧栏分组后，重跑 `npm test` 并确认 B9/B10 两个检查点；若在真实浏览器里出现「点了选项没反应」，优先检查该选项是否由 `pointerdown` 之后的真实点击触发（Base UI 的防误选机制）。
